## 1. Summary
1. **Zero-hardware inputs that work on this Mac today:** mouse/trackpad (Panel CHOP on a container), a stored clip through GPU vision built from ops that exist here (Composite `difference`, Cache TOP, Threshold, Blob Track TOP, Script TOP + OpenCV [V D: Farneback 42 ms]), any phone/tablet browser through Web Server DAT + WebSocket, OSC apps, MIDI [V T-34], keyboard. All ten plans in section 6 start from these and switch to a device later through one **Input Bus** (P1).
2. **What does not work here:** Multi Touch In DAT (Windows touch API only, in-build doc [S]); Kinect/Kinect Azure, Body Track, Face Track, Optical Flow TOP, NVIDIA Background TOP [V T-18]; Nvidia Flex Solver (class exists, Windows/NVIDIA, [S~]). Touch on a Mac therefore means a **browser page on an iPad/phone** or a **TUIO bridge**, not a native touchscreen op.
3. **Depth cameras:** the app bundle ships *universal* `librealsense2.2.56.5` and `libOrbbecSDK.1.10.16` and an *x86_64-only* `libdepthai-core` [B], which suits a Rosetta TD; Derivative's RealSense page still says the SDK "does not look like it will be updated for Apple Silicon" (v2.50 note) [S]. Orbbec on macOS needs root (launch TD with sudo) and has no body tracking [S]; RealSense skeleton is Windows-only [S]. Nobody found a 2025-26 Mac report of any of them working: **hardware test needed [U]**.
4. **Lowest-friction depth/body route on a Mac is an iPhone:** TDLidar v8 (Aristides Lintzeris, 8 Jun 2026) streams depth over NDI and body/hand/face over OSC; author claims 50-80 ms on Wi-Fi 5, ~30 ms on Wi-Fi 6 [S, vendor claim]. Needs iPhone X+ (LiDAR on Pro), iOS 18.6+, free app, Pro price inconsistent on its page ($9.99 vs $29.99): a spend, so the user's go-ahead.
5. **Interaction quality is mostly pattern, not sensor.** Documented findings: a proactive (animated) installation about doubled interaction vs a passive one (Twente thesis [S]); the Audience Funnel has six phases measured on 660 passers-by [S]; hand-distance control beat torso rotation in a 5-person museum test (Proxemic Museum, 2025 [S]); people discover with no signage when response is immediate (Vlny, Aug 2026 [S]).
6. **State machine + fail-safe is the pro layer:** idle(attract) -> engaged -> reward -> reset, hysteresis on every threshold, hold-last then fade to attract on signal loss, a heartbeat to a watchdog. Sources for exact numbers are thin (stillness settle 2-10 s is the only one found [S~]); the numbers in plans are starting values [U].
7. **Case studies:** only Sila Sveta (2021), Panorama "Infinity" (2016), q-bus (2010) publish an op-level tracking path; the 2025-26 Derivative posts found are mostly concept-level (Vlny, Bloom, Phosphene) or self-reported (MultiplayerServer_TD). Recorded as such in section 4.
8. **Nothing here was run.** Latency of the stored/Mac webcam path is **not measured**; P10 step 12 is the measurement.

## 3. Interaction patterns
| Pattern | What is documented | TD implementation | Source |
|---|---|---|---|
| Attract / idle | The idle look is the first thing a passer-by sees; if it does not draw them in "he will never find out" (Attraction Space, Borchers); proactive installation ~2x interactions vs passive; keep the attraction zone inside your own area | Idle scene always running on its own timeline; presence only crossfades layers (`switchTOP index blend` [D]) | hcipatterns; Twente |
| Audience funnel | 6 phases: passing by, viewing/reacting, subtle interaction, direct interaction, multiple interactions, follow-up; 660 observed at "Magical Mirrors" Berlin | Make phases 2-3 cheap: visible reaction to *any* motion before a hand/pose is recognised | Michelis & Mueller 2011 |
| Honeypot | Watching people interact attracts others; they queue behind (Brignull & Rogers 2003) | Mirror the active user big on the wall; leave room beside them | CHI refs |
| Interaction blindness | People cannot tell passive from interactive displays; animation/video cues helped (2016 poster) | Idle loop shows a "ghost user" doing the gesture (a recorded trail replayed through the same Input Bus) | Mueller 2009 [S~] |
| Proximity zones | Echo wall: dormant until people arrive, brightness rises as they get closer; Proxemic Museum: hand distance = zoom (best rated), arm span = reveal, torso rotation = distracting | `distance` CHOP -> `lookupCHOP`/`mathCHOP range` -> 3 zones (far/near/touch) with `triggerCHOP threshup/threshdown` hysteresis [D] | designboom [S~]; Kipp [S] |
| Presence / stillness | Stillness detector (ITP 2026): settling delay 2-10 s before "still", damping 3-20 s | `holdCHOP`/`timerCHOP` [D]: reward fires after N s of low motion energy | Faludi [S~] |
| Follow / avoid | Flocking = attract + repel + follow (Derivative tutorial [S~]); POP route: `forceradialPOP` `radialstrength` sign [D] | P6 | O file |
| Trail / paint / reveal | Feedback TOP + Composite over; silhouette trail = Cache + feedback (OSU "Mehmaan" 2026 [S~]) | P3, P4 | - |
| Per-person slot | q-bus IFA 2010: capped at 15, 15 particle components, freed slot re-assigned to next person or an unassigned one | `blobtrackTOP` ids -> slot table (`tableDAT`) | derivative.ca 60800 |
| Multiplayer | phones join by QR; server keeps state and batches input (Socket.io + Node + Docker, CNE Toronto, Jun 2026, self-reported 7,000 generation cycles) | P7 (pure Web Server DAT, no Node) | Vasily |
| Gesture vocabulary | Keep it to 3-4 reliable verbs: point/hover, pinch (angle thumb-index, 30 deg dead zone, ramp to +-1, Lag 0.05-0.1 s - Aristides.Lab 14 Mar 2026), open hand, hold-still. Hand tasks beat body rotation [S]. Gesture names come from MediaPipe `gesture_recognizer` (D file) | CHOP math on landmark pairs | derivative.ca 74152 |
| Time states | idle -> engaged -> reward -> reset is *my synthesis* [U] (no source found with all four); engaged needs a lose-grace (blob `revivetime`), reward a fixed length, reset a cooldown so a lingering person does not re-trigger | `timerCHOP` [D `length lengthunits start cycle outdone`] driven by a `chopexecuteDAT` [D `valuechange offtoon ontooff`] | P2 |
| Feedback cues | Response must be immediate so people self-discover (Vlny); show the *tracked* point (cursor/halo) so people see what the system sees | halo `circleTOP` at the bus x,y on top of every plan | derivative.ca 75264 |
| Accessibility | Operable parts 15-48 in (380-1220 mm) from floor (US arts-access guide [S~]); Auckland Museum wheelchair side-approach max 1370 mm touch point [S~]; Smithsonian: usable from a wheelchair position, not blocked by furniture [S~]; offer a non-body alternative (buttons/phone), a sensor+Kinect conflict at a student show was solved with physical buttons [S~] | Interaction zone sized for seated reach; Input Bus accepts phone/pad as a second source | see Sources |
| Onboarding | Prefer motion cue over text (above); the ghost-user replay doubles as signage; any text bilingual and short. No test data for Urdu signage found [U] | Text TOP overlay only in `idle` | - |

### Failure modes and how pros handle them
| Failure | Handling (and TD op) |
|---|---|
| Lighting change drifts background subtraction | Re-learn on a timer or button (`blobtrackTOP reset/resetpulse` [D]); slow-average background (Feedback TOP + Level `opacity` ~0.02 [D]) instead of one frozen frame; fixed exposure on the camera |
| Sun / floodlights on IR or ToF depth | First-gen Kinect structured light washed out outdoors; ToF better but "very noisy" in bright sun (arXiv 1707.09808; ISPRS 2023) [S~]. Shade/dusk or visible-light vision |
| Crowd merges into one blob / far people missed | Vision keys "a dense crowd as one blob" [S D]; set `maxblobsize`, use zones not identities, fall back to motion *energy* (no ID) |
| False triggers (shadows, passers-by) | `minblobsize`, `triggerCHOP mintrigger`+hysteresis [D], interaction zone mask (Crop/Level on the camera), dwell before "engaged" |
| Jitter / flicker | `lagCHOP lag1 lag2`, `filterCHOP` [D]; lag 0.05-0.1 s is the documented starting range [S] |
| Dropouts mid-gesture | Blob revival (`reviveblobs`, `revivetime`, `revivedistance`) [D]; hold-last 1-2 s then fade to idle |
| Sensor / app dies | Heartbeat: watchdog restarts app if pings stop (TDWatchdog, Vasily, 2 May 2024: "Ping every", max errors, restarts app, then system; shipped as `.exe`, **Mac unconfirmed** [S]); Stalker for 088/099 [S~]; on Mac use `launchd` or an external heartbeat script [U]. Camera loss -> idle layer keeps running (RUNTIME layer-6 rule, D file) |
| Calibration (camera -> screen) | Palette `quadReproject`, `kantanMapper`, `camSchnappr`, `kinectCalibration` [B]; `cornerpinTOP` [D `pintopleftx...`] on the camera image with 4 draggable corners saved to a table [U]; OpenCV `findHomography` for a webcam-to-projector map [S~] |
| Two sensors fight (ultrasonic vs Kinect at a student show) | One owner per sensor, merge in the Input Bus, never read the same port twice [S~] |

## 6. Top 10 build plans (each <= 15 steps; P1-P8 and P10 need no hardware)
Conventions: scratch COMP `/project1/_probe_AE_<n>` (T-20); one structural change per call + `td_errors` (T-31); viewers on, `td_layout` at the end (T-40/T-49); unviewed ops do not cook (T-02): give every chain a consumer; Script TOP per-frame work guarded by `absTime.frame` (T-21); Circle TOP `centerx` units: read the par first (T-23). Never `open -a` TD (T-24). "Out" = Null TOP/CHOP named `OUT`.

**P1 Input Bus + simulator** (data only; preview 1280x720). Every other plan reads `in_bus/OUT`: channels `x y present vx vy energy` (0-1) + `blobs` table.
1 `containerCOMP in_bus`; custom pars (td_custom_pars): `Source` menu sim|mouse|clip|device, `Smooth` 0.15, `Threshold`, `Mirror`. 2 Sim: `noiseCHOP` [D `type period amp offset channelname`] two channels `x y` (period 4, amp .35, offset .5) + `lfoCHOP` square [D `wavetype frequency`] 0.05 Hz -> `present`. 3 Mouse: child `containerCOMP pad` + `panelCHOP` (`component` = pad, `select` `u v select`) -> `renameCHOP` x y present. 4 Clip: `moviefileinTOP` -> `resolutionTOP` 320x180 -> `monochromeTOP` -> P4 mask -> `analyzeTOP op average` (mask) and (mask x `rampTOP` U/V) -> `toptoCHOP` -> `mathCHOP` divide = centroid; `present` = mask average > Threshold. 5 Device: empty `selectCHOP` slot for Blob Track / OSC (TDLidar) later. 6 `switchCHOP index` = Source. 7 `lagCHOP lag1 Smooth`; `slopeCHOP` -> vx vy; `triggerCHOP threshup .30 threshdown .15 mintrigger .3` on `present` (hysteresis). 8 `energy` = `analyzeCHOP average` of |v|. 9 Preview: `circleTOP` at x y over a ramp. 10 `OUT` Null CHOP; test each Source, `td_errors`. Switch to the real device = change one menu.

**P2 Presence state machine + attract loop** (1920x1080 wall; no hardware, uses P1 sim).
1 Idle scene: `noiseTOP` [D] slow drift + `textTOP` prompt. 2 Engaged scene: halo circle at bus x y + trail (P3). 3 Reward scene: `rampTOP` burst + `textTOP`. 4 `switchTOP index` blends the three. 5 `timerCHOP` [D `length` 6 `lengthunits seconds` `start` `outdone`] for reward; second timer = cooldown 4 s. 6 `chopexecuteDAT` [D `chop` = present, `offtoon ontooff`] sets state: present on -> engaged; present off for > `revivetime` 1.5 s -> idle; engaged and `energy` < .05 for 3 s -> reward -> reset (cooldown, ignore `present`) -> idle. 7 State in a `tableDAT` + `constantCHOP state`; `lagCHOP` on the switch index (cross-fade 0.5 s). 8 Idle replays a recorded 6 s path as the "ghost user": capture bus x y with `recordCHOP` [D `record sample output reset`] (or store rows in a `tableDAT`) and play it back through `dattoCHOP` [D `dat output`] into the idle scene's halo. 9 Log transitions to a `textDAT`. 10 Test with sim cycle 20 s; check no state sticks.

**P3 Trail / paint canvas** (1920x1080; feedback is cheap; 3840x2160 later). Input: bus x y present.
1 `circleTOP` radius .02 at bus x y (`centerx` units, T-23), alpha = present. 2 `feedbackTOP` [D `top`] -> `levelTOP opacity .96` (decay) -> `compositeTOP` [D `operand over|add`] with the circle -> `nullTOP OUT`; set Feedback `top` = Composite output. 3 `blurTOP size 2` in the loop for soft trails. 4 `rampTOP` hue by time -> circle fill (`fillcolorr/g/b`). 5 Speed-scaled radius: `vx vy` length -> radius. 6 Wipe: `feedbackTOP resetpulse` on reward->reset. 7 `edgeTOP` or `displaceTOP` [D] for a ink-glow pass. 8 Mouse source for a first live look; compare Sim. 9 Read `td_perf`; trails must stay at project fps.

**P4 Silhouette reveal mask from the stored clip** (output 1080x1920 portrait, e.g. retail window / tall LED; source clip is 1920x1080, `fitTOP` crop to the person).
1 `moviefileinTOP` clip loop -> `resolutionTOP`. 2 Background: `cacheTOP` [D `cachesize` 30 `step`] output frame 0 is *wrong* (person in clip): instead a slow average = `feedbackTOP` + `levelTOP opacity .02`; or use frame difference vs `cacheTOP` delayed by 5 frames (motion only). 3 `compositeTOP operand difference` current vs background. 4 `monochromeTOP` -> `thresholdTOP` [D `comparator greater threshold .08 soften .05`] -> `blurTOP` (feather). 5 Optional upgrade: Apple-Vision person mask from the helper (T-27) replaces steps 2-4 for a clean silhouette. 6 `compositeTOP` (or `overTOP`) hidden image/video through the mask; second layer = idle image. 7 `blobtrackTOP` on the mask for count/bbox -> bus `blobs`. 8 Mask opacity driven by bus `present` (fade-in). 9 `fitTOP` 1080x1920 `OUT`. Latency here is offline clip; real webcam adds camera latency [U].

**P5 Motion flow -> particles** (1920x1080; Farneback in Script TOP measured 42 ms [V D], i.e. ~20 fps flow: run flow at 320x180, particles at full rate).
1 Source clip -> `resolutionTOP` 640x360 -> `monochromeTOP` (and later webcam). 2 `scriptTOP` [D `callbacks`] `onCook`: `cv2.calcOpticalFlowFarneback(prev, cur, None, .5,3,15,3,5,1.2,0)`; keep `prev` in a module dict; skip if `absTime.frame` unchanged; write flow as RG float via `copyNumpyArray`; output 320x180 32-bit. 3 `levelTOP`/`mathCHOP` gain. 4 POP chain (O file F-chain): `pointgeneratorPOP` -> `particlePOP` [D `maxparticles birthrate life damping targetpop`] -> `lookuptexturePOP` [D `top`] sampling the flow TOP at each point's screen UV -> `mathPOP` multiply into `Vel`/force -> `nullPOP` (= `targetpop`). 5 `geometryCOMP` instancing from the Null (`instanceop`, T-15) + `cameraCOMP` ortho + `renderTOP`. 6 `feedbackTOP` trails. 7 Fallback: if the Script TOP lags, drop to 240x135 or every 2nd frame. The force chain is **unverified [U]** (A-file B-note); verify before relying.

**P6 Follow / avoid with proximity zones** (1080x1920; POPs, uses bus x y).
1 `pointgeneratorPOP` 50k points (rectangle) -> `particlePOP`. 2 `forceradialPOP` [D `posx posy posz radial radialstrength falloff falloffradius spiral`] position = bus x y (map to world with `mathCHOP`), `radialstrength` negative = attract, positive = avoid. 3 `noisePOP` [D `curl2d`] idle swirl. 4 Zones: bus distance-to-centre -> `lookupCHOP` -> strength: far = gentle attract, near = strong avoid, touch (`present` and speed) = burst (`particlePOP` birth pulse). 5 Hysteresis on zone edges (`triggerCHOP`). 6 `limitPOP` [D] caps velocity. 7 Render as P5 step 5. 8 Two pointers: duplicate `forceradialPOP`, positions from `blobs` rows 0 and 1. 9 Idle: force strength lerps to the noise field via the P2 state.

**P7 Phone pad, multi-user, QR** (1920x1080; zero hardware: two browser tabs on this Mac, then a phone on the LAN; LAN only, no internet exposure).
1 `textDAT clientHtml`: page with a full-screen `<canvas>`, `pointerdown/move/up` -> `ws.send(JSON {id,x,y,down,pressure})` (Pointer Events `pressure` [S MDN]); client id from `crypto.randomUUID()`. 2 `webserverDAT` [U pars `active port callbacks`] port 9980, callbacks `onHTTPRequest` returns `clientHtml.text`, `onWebSocketReceiveText` parses JSON into a `tableDAT players` row per id (cap N=8, free slot on `onWebSocketClose`; q-bus slot idea). 3 `tableDAT players` -> `dattoCHOP` [D `dat extractrows output`] (or a `scriptCHOP` [D]) giving channels `p0x p0y p0down ...`. 4 Draw each cursor as `circleTOP` instanced from the CHOP (`geometryCOMP` instancing from CHOP, T-15 pattern) or N circles composited. 5 Per-player colour by slot. 6 Stale cursors (no message 1.5 s) fade. 7 QR: show the URL as large text first; QR image generated outside TD and loaded (`moviefileinTOP`) - no QR op in this build [D]. 8 Secure option: `secure` + cert for iOS DeviceMotion [S MDN]. 9 Bus `Source = phone` uses player 0. 10 Never forward the port to the internet (article warns no auth [S]); Basic auth exists [S].

**P8 Physics playground** (1920x1080; Bullet is CPU, no GPU/OS caveat found; Flex is Windows).
1 `geometryCOMP` ball + `actorCOMP` [D `mass friction rest linvelx...`] x 30, with `bulletsolverCOMP` [D `actors forces gravityy play feedback`] gravity -9.8. 2 Floor/walls as static actors (`kinstate`). 3 `renderTOP` ortho. 4 Pointer body: a kinematic actor (`kinstate`) at bus x y, velocity set each frame from bus `vx vy` (Bullet doc: override velocity, not position, via `Bullet Solver CHOP` + `feedback` pars; Palette `multiTouch` is the worked example [S]). 5 `forceCOMP` [D `forcex strength radius falloff`] as a local gust where `present`. 6 Reset: `bulletsolverCOMP initialize` on state `reset`. 7 Sleep inactive bodies (idle). 8 Cap bodies so cook stays < 8 ms (`performCHOP cookrate` [D]).

**P9 Sensor + DMX bridge** (data + 1280x720 dashboard; runs in simulation first).
1 Sim sensors: `noiseCHOP` -> `distance_cm`, `lfoCHOP` square -> `pir`, `noiseCHOP` -> `touch0..3`. 2 Real later: Arduino/ESP32 prints `d=123,p=1,t=0` per line -> `serialDAT` (Per Line; close Arduino Monitor) or `oscinCHOP`/`udpinDAT`; parse in a `datexecuteDAT`. 3 Same channel names into the Input Bus slot `device`. 4 Median-3 + `lagCHOP` ; debounce PIR with `holdCHOP` 10 s. 5 Zones from distance (near < 120 cm). 6 Lights: `mathCHOP` -> `dmxoutCHOP` [U `interface artnet`, `format packetpersample`], 512-channel frame with dummy channels. 7 **Output to `127.0.0.1` / a loopback Art-Net monitor first**; any real-network universe waits for the user's go-ahead. 8 Show a dashboard `textTOP` of values + last-seen age per sensor. 9 Sensor silent > 3 s -> bus `present` 0, lights to a safe scene.

**P10 Robustness layer: calibration UI, smoothing, watchdog, latency probe** (1280x720 control panel; wraps every plan).
1 `cornerpinTOP` [D `pintopleftx pintoplefty ...`] on the camera/clip with four slider pairs; save to a `tableDAT` (store/recall). 2 Threshold panel: sliders for Blob Track `threshold minblobsize`, Level, Smooth; live mask preview. 3 `Test` button pulses `blobtrackTOP resetpulse` (re-learn). 4 Signal-health CHOP: frames-since-change of x y (`timerCHOP`), `performCHOP` fps [D `fps cookrate droppedframes`]. 5 Lost-signal rule: hold last 1.5 s -> fade `present` to 0 -> idle. 6 Heartbeat: `webclientDAT` or `udpoutDAT` ping once a second to an external script; script restarts TD if pings stop (design after TDWatchdog; Mac packaging [U]). 7 Auto-reset: state machine (P2) returns to idle after 60 s of no `present`. 8 `textDAT` event log (state changes, errors). 9 Kill switch: `Source = sim` forces the ghost loop. 10 Flash/brightness guard for LED walls: see R file. 11 `td_errors` + `td_perf`. 12 **Latency probe:** show a frame counter on a second screen, film screen + camera with a phone at 240 fps (or compare `absTime.frame` stamp when a visible LED toggles in the clip), count frames between event and on-screen reaction; write the number to LEARNINGS (T-nn) - none exists yet.
