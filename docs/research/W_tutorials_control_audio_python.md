# W - Tutorials for control, signal, audio-reactive and Python (web research, 26 Oct 2026)

Task: find real TD tutorials beyond GLSL that an agent driving TD 2025.31550 (macOS, Rosetta, via `jazib-td`) can learn from: CHOP signal
work, audio-reactive, tempo/timecode, data-driven DATs, Python/extensions, custom pars/components, UI, OSC/MIDI, show control.
Research only: no TD call, nothing downloaded or installed, **no video was watched** (I cannot play YouTube). Every title/author/date/URL
below was read on its page in this session; what a tutorial "teaches" comes from the page's own text, not from the video.
Does not repeat the rules in `K_audio_reactive.md` or the panel build in `H_control_panel.md`; it adds sources and op-by-op recipes.

Tags: **[V]** = page or doc read this session (URL given). **[S]** = seen only in a search snippet / listing, page not opened.
**[U]** = unverified: my own design, a par name not in our dump, or a claim from memory. **[D]** = par/op name confirmed in our live dump
(`ops/ops_*_2025.31550.json`) or `ops/CHOP.md`. Video length: derivative.ca pages almost never state it, so "n/s" = not stated.

## 0. Summary

1. **Best free, current sources are Derivative's own community-tutorial index (`derivative.ca/tags/<tag>`, readable) and the Interactive &
   Immersive HQ (elburz) posts there.** The tag pages `audio-reactive`, `audio`, `chop`, `midi`, `osc`, `parameters`, `ui`, `show-control`,
   `cuespresets`, `state-machine`, `json`, `api`, `tdableton` list real, dated items up to 24 Oct 2026. Most carry a YouTube link; the page text
   is a 2-3 line blurb, so the **op chain is only in the video** - an agent needs a human-written chain or the docs, not the page.
2. **Matthew Ragan's written Python series (2015-2019) is the only deep, text-first source** on extensions/modules/executes/dictionaries-as-presets,
   and Derivative's own Extensions doc links his "Understanding Extensions". It is old (2015-16, "50000 series") but the class-in-a-Text-DAT,
   capitalised-name-promotion pattern is still what the current docs describe [V]. His newer material is paid (IIHQ Pro).
3. **Beat detection:** the classic is elekktronaut's "Beat Detection" (13 Feb 2020, reusable kick+snare CHOP component); Derivative's palette
   `audioAnalysis` COMP is the shipped alternative (Low/Mid/High, Kickdetection, Snaredetection, Rythm; per-band Threshold/Smooth/Gain/Add) [V].
4. **New in 2025-26 and relevant to us:** (a) POP-based audio-reactive (IIHQ 21 Oct 2025, elburz 19 Oct 2026); (b) **Timecode CHOP** tutorials
   (29 Feb 2024; "New Timecode Features", 23 Oct 2026); (c) free **Table-Driven FSM** `.tox` (Mar 2026) and **Custom Cuelist Sequencer** (Dec 2025);
   (d) function.store's `CHOP Anatomy` (Oct 2025) and the "Constant CHOPs are a bad idea" custom-parameter argument (Mar 2025);
   (e) the Aug 2025 Music Hackspace/Derivative meetup on extensions and callbacks (Pydantic validation, CallbackManager).
5. **Not found / could not verify:** nothing for **Paketa12** on control/audio/Python (only a mention in another author's post); nothing for
   **Ian Shelanskey**; **Zoe Sandoval** appears only as Ragan's co-presenter (2019 Summit external-Python repo, ACCAD workshop 2025), no
   standalone tutorial. A Ragan "presets and cue building" tutorial was *not* confirmed (a forum mention only) - do not cite it.
6. **Mac/2025 flags:** no tutorial read was Windows-only. Three real Mac risks: **EssentiaTD** (best analysis CHOPs) lists "macOS (Apple Silicon)" only,
   AGPL-3.0, mono input - our TD runs under **Rosetta** so an arm64 plugin may not load [U]; **MIDI devices missing** in this build (see `ops/CHOP.md` §1);
   **Audio Device In** needs the mic permission and has a reported "no source" case (`ops/CHOP.md` §2).
7. **MCP can reproduce almost all of the signal/Python/DAT recipes** (create ops, set pars, `td_exec` Python, `td_custom_pars`, `td_dat_text`); it
   cannot hear audio, move a MIDI fader, or judge a look, and drag-based widget layout is only partly reproducible by setting pars.

## 2. The 12 recipes (live concert rig)

Par names tagged [D] are in our dump; [U] = not in the dump (Audio Device In, MIDI In, OSC In, Web Client, Trim, Null not dumped) - run `td_get_pars`
on the new op first. Build each inside one Base COMP, end each chain in a **Null named for the signal** (export from the Null, `H_control_panel.md`).
Hearing the result needs the human; the agent verifies by `td_get_pars`/Info CHOP values and `td_errors`.

**R1 Audio source with fallback.** (1) `audiodeviceinCHOP` (driver CoreAudio, pick channels, small Buffer Length) [U]. (2) `audiofileinCHOP` `file`=set track, `play`=1, `repeat`=on, `volume` [D]. (3) `switchCHOP` index = custom int par `Audiosrc`; wire both in. (4) `mathCHOP` `gain` = custom par `Trim`. (5) `nullCHOP` `n_audio`. Risk: Mac mic permission/"no source" (`ops/CHOP.md` §2) - default to the file until the human confirms the live device. Audio File In plays a bundled mp3 by default: set `file` first.

**R2 Three bands + levels (no palette).** From `n_audio`: three `audiofilterCHOP` [D `filter` lowpass/bandpass/highpass, `cutofffrequency`] at ~120 Hz low, ~1-2 kHz mid, ~6 kHz high -> each `analyzeCHOP` `function`=rmspower [D, per `ops/CHOP.md`] -> `mathCHOP` `gain`/`postoff` (per-band custom pars) -> `lagCHOP` `lag1`=0.03 (rise), `lag2`=0.25 (fall) [D] -> `mergeCHOP` -> `renameCHOP` `low mid high` -> `n_bands`. Cost is tiny (3 filters).

**R3 Kick pulse with refractory time.** `audiofilterCHOP` lowpass 120 Hz -> `analyzeCHOP` rmspower -> `lagCHOP` (`lag1` 0.01, `lag2` 0.15) -> `mathCHOP` gain (threshold knob = custom par) -> `triggerCHOP`: `threshup`=0.5 (custom par), `triggeron`=increase, `retrigger`=0.15 s with `retriggerunit`=seconds, `attack`=0, `peaklen`=0.05, `decay`=0.2, `release`=0 [all D] -> `n_kick`. The 0.15 s refractory keeps well under the 3 flashes/s rule in `K_audio_reactive.md`. Extra cheap alternative: Audio Spectrum (`mode` visual, `fftsize` 2048, `frequencylog`=1, `outputmenu`=setmanually, `outlength`=256 [D]) then Trim to the bass bins [U].

**R4 Palette analyser as baseline.** Load the shipped `audioAnalysis` tox (path under `Palette/Tools/` in `ops/PLATFORM.md`; `td_tox_load`) [U path]. Wire `n_audio` to input 0. Set `Kickthresh`, `Snarethresh`, `Lowthresh/Midthresh/Highthresh`, `Lowsmooth...` [V doc]. Read channels `Low Mid High Kickdetection Snaredetection Rythm` with a Select CHOP. Turn off analyses not used (doc advises it). Use it first to hear what "good" looks like, then compare to R3.

**R5 Auto-gain so a quiet and a loud act both fill the range** (idea from MechBullRodeo #7 [S], build is my design [U]). From a band channel: (1) `lagCHOP` `lag1`=0.05, `lag2`=20 s -> slow peak follower `peak`. (2) `mathCHOP` with two inputs, `chopop`=divide (signal / peak; verify menu value) -> clamp with `limitCHOP` `type`=clamp, `min` 0, `max` 1 [D]. (3) Floor: `mathCHOP` `postoff` = custom par `Floor` so silence does not amplify noise (gate on peak < floor). (4) Custom pulse par `Reset` -> `lagCHOP` `resetpulse` [D]. Rule: gain changes slowly, never within a bar.

**R6 Tempo: tap, Link, nudge.** (1) `beatCHOP`: `playmode` locked or global, `period` 4 (= 1 bar), outputs on: `ramp`, `pulse`, `beat`, `bar`, `sixteenths` [D]; only ONE Beat CHOP with `updateglobal` on. (2) Tap: custom pulse par `Tap` -> `td_exec` `op('/local/time').tempo = <bpm>` for typed BPM [V Beat doc]. (3) Link: `abletonlinkCHOP` `enable`=1 [D]; `chopexecuteDAT` on its `tempo` channel `valuechange` -> `op('/local/time').tempo = round(val,2)` [U: Link does not feed the global clock by itself, per search result]. (4) `n_beat` Null. Leave Link off unless the user confirms the band runs Live/Link.

**R7 Reusable look component with custom page + extension.** (1) `baseCOMP` named after the look. (2) `td_custom_pars`: page `Look`, floats `Intensity`, `Speed`, toggle `Active`, pulse `Reset` (capitalised, no spaces). (3) `textDAT` `LookExt` with `class LookExt:` `__init__(self, ownerComp)`, methods `Fire(self)`, `Reset(self)`, `onInitTD(self)` [V Extensions doc]. (4) On the Base set `ext0object` = `op('./LookExt').module.LookExt(me)` [U exact expression], `ext0name` LookExt, `ext0promote` on, `initextonstart` on [D], pulse `reinitextensions`. (5) Persistent values via `StorageManager` or `self.ownerComp.store(...)`; never rely on `__init__` for anything needing other ops (use `onInitTD`). (6) Test: `td_exec` `op('look1').Fire()`. Capital letters are what make a method promote [V Ragan #24].

**R8 Operator panel in 4 ops.** `parameterCOMP` `op`=the state COMP, `pagescope`=`Look`, `labels` on [D] -> inside a `containerCOMP` (`w`,`h`) -> `windowCOMP` `winop`=that container, `winw`,`winh`, `borders` off, `alwaysontop` as needed [D]; open with `ui.performMode = True` via `td_exec`, exit Esc / F1 [V Perform doc]. Fast, themed later with Widgets (#40). Use only on the control machine; Window COMP `performance` par on the output window stays user-gated (`R_show_safe_interactive.md`).

**R9 MIDI/OSC in as "fill rows" mapping.** (1) `midiinCHOP` / `oscinCHOP` (port, address) [U]. (2) `tableDAT` `map`: columns `source_channel, target_path, par, lo, hi, curve`. (3) A `scriptDAT`/extension method `Apply()` loops rows: `v = op('midi_in')[src].eval()`; `tdu.remap(v,0,127,lo,hi)`; `op(target).par[par] = x` or build `Bind CHOP` with `pickup` on [D] for faders. (4) Rebuild on `datexecuteDAT` `tablechange` [D]. Plug MIDI devices in BEFORE launching TD (`ops/CHOP.md` bug). Learn-mode (TDMap-style) is the only part that needs a human moving a knob.

**R10 Cue list: Table DAT + Timer CHOP segments.** (1) `tableDAT` `cues`: `cue, look, fade, hold` (rows = cues). (2) `timerCHOP`: `timecontrol`=sequential, `segdat`=`cues`, `segmethod`=serial, `ondone`=donothing, `callbacks` DAT [D], outputs `segment`, `timer_fraction`, `done_pulse` [V]. (3) In callbacks: `onSegmentEnter(timerOp, segment)` -> `ext.Show.Goto(op('cues')[segment+1,'look'], fade)`; `onDone` -> safe/house look. (4) Custom pars `Go`, `Stop`, `Cue` on the Base -> pulse `start` / `initialize`. (5) For timecode-driven acts: `timecontrol`=timecode with `ltcinCHOP` (needs an LTC feed) [D]; confirm ready state with `timerOp.ready`. Prior art to borrow, not adopt blind: Cuelist Sequencer (#47), CuryCue (#49).

**R11 Show state machine with watchdog.** (1) `tableDAT` `states` (`state, look, timeout, next`) and `tableDAT` `events` (`from, event, to, guard`). (2) Extension `ShowExt`: `Fire(event)` finds the row in `events` where `from` == `current` and `event` matches, runs the named guard (Python function; block if False, as in the FSM asset's `onGuard` [V]), sets `current`, calls `Goto(look)`. (3) Timeout: `run('args[0].Fire("timeout")', self, delayMilliSeconds=ms, group='fsm')` and cancel earlier runs with `runs`/`kill()` [V Run Class: `kill()`, `group`, `runs`]. (4) Heartbeat: a `lfoCHOP` or `timerCHOP` `onTimerActive` writes a timestamp; `chopexecuteDAT` fires `Fire("stale")` if the audio level is silent for N s -> fall back to a "safe look" state. (5) Log each transition to a `textDAT` log (`td_dat_text`). This is the plain-Python equivalent of #46; check that repo before writing our own.

**R12 Data in: setlist/cue JSON and a REST poll.** (1) `textDAT` loaded from a file (`file` par, `syncfile` on) holding the setlist JSON (e.g. exported from `prismfest26-show/show.json` - read-only copy, never write back) -> `jsonDAT` [D: `output`=results, `filter`=$, `holdlast`] -> `selectDAT` / `evaluateDAT` to rows [D]. (2) For live REST: `webclientDAT` `reqmethod`=GET, `url`, `verifycert` [V]; pulse `request` from a `timerCHOP` `done_pulse` set to cycle every N s (rate-limit; never every frame); parse in its callback DAT (`onResponse` signature: verify in the DAT template [U]). (3) `datToCHOP` (type name [U]) turns numeric columns into channels for looks; keep string fields as DATs. (4) Validate before use (type/range checks; the Pydantic idea of #29 [V]) and keep the last good table so a bad response cannot blank the wall. (5) Cook cost: gate polling off during the show if no source needs it.
