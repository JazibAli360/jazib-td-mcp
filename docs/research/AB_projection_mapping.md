## 0. Summary
1. **Two mapping modes, 7 palette tools.** 2D: `kantanMapper`, `stoner`, `cornerPinPOP`/`cornerPinSOP`, built-in Corner Pin TOP. 3D: `camSchnappr` (+`sweetSpot`, `kantanUVHelper`). Multi-projector: `projectorBlend`, camSchnappr Auto Blend. LED/screens: `quadReproject`. All in `Palette/Mapping/*.tox` [D] (section 1).
2. **camSchnappr is scriptable far beyond what its docs say.** Its promoted Python extension (`op(...).Calibrate()`, `.Clear()`, `.MoveActive()`) runs `cv2.calibrateCamera` over two Table DATs (`objPtTbl`, `imgPtTbl`) inside the Project Camera COMP [D, read from the .tox]. An agent can fill the tables and calibrate with no mouse. Only *choosing real-world points* needs a human. cv2 exists in this TD (T-19).
3. **Virtual room = the test bench.** Light COMP has a real projector-map feature (`projmap`, `projmapmode`, `projangle`, extend/filter pars) [D]; a Camera COMP has lens shift (`winx/winy/winsize`), custom projection matrix and Quad Reproject pars [D]. So projector -> room -> viewer can be simulated with zero hardware (P1), and camSchnappr can be unit-tested against a known ground-truth camera (P4).
4. **Kantan Mapper 2 and Stoner are GUI-only to author, but both store plain data** (Kantan: JSON via `Collect()/Load()`; Stoner: tables in the Project COMP + a displacement map for a Remap TOP). Their `Load/Collect` call `ui.chooseFile`, a modal dialog that blocks the MCP (PLATFORM.md): never call them from `td_exec`.
5. **No built-in mesh-warp TOP.** Mesh warp = Stoner (4x4 Bezier grid default) or Kantan quad gridwarp or your own Remap TOP with a displacement map. Corner Pin TOP has `mapping` bilinear/perspective [D].
6. **Edge blend:** `projectorBlend` implements Paul Bourke's method (adapted from ofxProjectorBlend, MIT-style licence text inside the .tox) [D][V]: array NxM, per-projector overlap/blankout/power/luminance/gamma, per-side control. **No black-level uplift anywhere in TD**; build it with masks (P5, [U]).
7. **Mac:** every mapping palette tool is plain TD nodes, no OS gate on the doc pages [V]. Gates that bite: Mission Control "Displays have separate Spaces" must be OFF, Mirror Displays OFF, one Window COMP spanning all outputs beats several [V Multiple Monitors]. **Windows-only:** Scalable Display TOP [V] (and `viosoTOP`, `scalabledisplayTOP` are "not created" on this Mac [D]), Nvidia Mosaic/Surround/AMD Eyefinity spanning, Artio (listed for Windows, GPL-3 [V]), Spout, Kinect calibration palette (device).
8. **LED vs projection:** LED needs no geometric calibration and no blending; the only 3D trick that carries over is **Quad Reproject / sweet-spot anamorphic content** (pixel-exact per panel, view-dependent) (P6).
9. **Content that reads on mapped surfaces** is almost always 3D-model driven: render from the projector (or audience) viewpoint, mask to architecture, fake light/wireframe/collapse built from world-position and depth passes (section 2 rows 19-26, P7).
10. **Human steps are few and short:** pick/align >= 6 points in camSchnappr, nudge Stoner/Kantan handles, set projector physical state (reset keystone/zoom, focus, lens shift), choose the output monitor. Everything else is MCP-buildable (section 3).

## 3. Calibration workflow: what needs a mouse and what the MCP can script
| Step | Needs | MCP can do |
|---|---|---|
| Physical: projector placed, focus, zoom set, **keystone/digital zoom reset**, lens shift noted | human | record values in a table |
| Choose output monitor, extend (no mirror, Spaces off) | human + Mission Control | `monitorsDAT` list; set `Monitor`/`display` |
| Model: scan (photogrammetry), clean-up, UV | external tools | import FBX/OBJ/USD (`fbxCOMP`, `fileinSOP`, `usdCOMP`), reduce points, check UV via Render TOP uvunwrap |
| camSchnappr points (>= 6) | human drag/Ctrl+click **on the projector's output window** | fill `objPtTbl`/`imgPtTbl`, `Calibrate()`, read `Calibrationerror`, copy extrinsics to the real camera, save |
| Fine warp | human drag (Stoner/Kantan) | bake displacement map, verify with rig, remove Stoner |
| Blend and black level | human reads seams by eye/camera | all pars, masks, tests via `analyzeTOP` |
| Perform output | user approval to take over a display | Window COMP pars; `ui.performMode` only on approval |
| Verify | camera photo or user eyes | `td_screenshot` of TOP viewers only; no physical-surface check |

## 5. Build plans (top 8, ordered by dependency and value; each <= 15 steps)
Conventions: container `/project1/pm_rig` (`baseCOMP`); `W,H` = projector resolution chosen per use case (default 1920x1080); `td_layout` flow + `td_errors` after every structural step (LEARNINGS T-31/T-40); one structural change per call; viewers on; no Window opened without the user. Names are suggestions.

### P1. Virtual room test rig (foundation for P2-P8)  [Light COMP projmap behaviour = U, test at step 7]
1. `baseCOMP pm_rig`. Custom pars (td_custom_pars): `Pw`=1920, `Ph`=1080 (projector), `Vw`,`Vh` (viewer preview, e.g. 1080x1920 for PF26 or 1280x720).
2. `geometryCOMP room` + `boxSOP room_box` (`sizex`6 `sizey`3 `sizez`8, `ty`1.5, `texture`=boxinside, `normals`=on) + `phongMAT room_mat` (`diffr/g/b`0.8, `ambr/g/b`0.05); room COMP `material`=room_mat.
3. `geometryCOMP target` + `boxSOP target_box` (`sizex`1.2 `sizey`1 `sizez`1.2, `tz`-1.5, `ty`0.5, `ry`20) + `phongMAT`; also a flat `gridSOP screen` (`orient`=xy, `sizex`3 `sizey`1.7, tz -3.9) as a wall screen.
4. `nullSOP model_target`, `model_screen`, `model_room` = the same geometry (objectmergeSOP) inside `geometryCOMP model`, `constantMAT model_mat` (`colormap`=`content`, `colormapcoord`=uv0).
5. `content` TOP at `Pw`x`Ph`: `rampTOP` + `textTOP` corner labels + `rectangleTOP` frame (asymmetric so flips are visible) -> `nullTOP content_out`.
6. `cameraCOMP proj_true` (`tx`0.8 `ty`1.4 `tz`3.4, `lookat`=target, `viewanglemethod`=vertfov, `fov`35, optional `winy`0.1 lens shift). `renderTOP proj_render` (`camera`=proj_true, `geometry`=model, `lights`=empty, `outputresolution`=custom `Pw`x`Ph`) -> `nullTOP proj_out`.
7. `lightCOMP proj_light`: `lighttype`=cone, `projmap`=proj_out, `projmaptype`=spot, `projmapmode`=useview, `fov`=35 (+ `viewanglemethod` vertfov), `projmapextendu/v/w`=zero, `projmapfilter`=linear, `dimmer`1, `tx/ty/tz/rx/ry/rz` = expressions from `proj_true`. Test: if the viewer shows no image in step 9, try `projmapmode`=simplehorzfov + `projangle`, else `lighttype`=distant/point; record in LEARNINGS.
8. `ambientlightCOMP amb` (`dimmer`0.02) so the room is nearly dark without projection.
9. `cameraCOMP view_cam` (`tx`-2.5 `ty`1.6 `tz`5 `lookat`=target, `fov`50) -> `renderTOP view_render` (`geometry`= room target screen, `lights`= proj_light amb, `outputresolution`=custom `Vw`x`Vh`) -> `nullTOP view_out`.
10. Check: viewer sees `content` stuck on `target`, `screen` and walls where the projector sees them; image extends only inside the frustum.
11. Misalign test: add `ty` +0.05 on a `target_real` offset COMP; the viewer shows drift => the rig can score alignment.
12. `analyzeTOP` (`op`=average) on `view_out` and a difference with a reference render = alignment metric for later plans.
13. `td_layout` flow; `td_screenshot` of `view_out`; `td_save_project`.

### P2. Corner pin one surface (any size)
1. P1 up; choose `screen` as surface; set `proj_true` so the image is skewed.
2. In `td_exec`: for the 4 screen corners (world positions from `screen` SOP) compute image-plane position via the camera: `m = cam.projection(Pw,Ph) * inverse(cam.worldTransform) * Position(x,y,z)`; verify the result range (NDC vs pixels is **U**); normalise to 0-1 with y up.
3. `cornerpinTOP pin`: input `content_out`; `outputresolution`=custom `Pw`x`Ph`; `mapping`=perspective; set `pinbotleft/botright/topleft/topright` x,y with unit=fraction; `bgcolora`=0; `extend`=zero.
4. Change model: `model_mat` colormap = `pin` for screen only (a second constantMAT for `screen`), keep `proj_render` on the room as before; or feed `pin` direct as `proj_out` to the Light.
5. Viewer: `view_cam` fronto-parallel to `screen`: image appears as an upright rectangle. Score with `analyzeTOP` on a difference vs `content_out` resized.
6. Try perspective vs bilinear (`mapping`); with high-angle pins bilinear shows creases.
7. Save pin values to a Table DAT `pin_store`; layout; save.

### P3. UV-based 3D mapping with a calibrated camera (content template included)
1. P1 up. Use the target as an L-shaped solid: `boxSOP` x2 -> `mergeSOP` -> `textureSOP`(`type`=xyznorm or `face`) -> UV layer 0.
2. UV template: `renderTOP uv_tpl` (`rendermode`=uvunwrap, `uvunwrapcoord`=uv0, `outputresolution` 2048x2048) with a wireframe `phongMAT` (`wireframe`=topology, `overridemat`) -> save PNG (`TOP.save`) for artists.
3. Content in UV space: `noiseTOP` + `textTOP` + `edgeTOP` per face using `uv_tpl` as a mask (select faces by colour).
4. `constantMAT uv_mat` (`colormap`=uv content, `colormapcoord`=uv0, `colormapcoordinterp`=perspectivecorrect) on `model_target`.
5. Projector render as in P1; viewer renders target with the projector light.
6. Test: rotate `target` slightly in `proj_true` only (reality) => note misfit; this is what camSchnappr fixes (P4).
7. Add per-face brightness `levelTOP` before the colormap for visual debug; add `cullface`=backfaces on `proj_render` (`renderTOP`) to hide the back side.
8. Document: UV island count, texel density, content res; save.

### P4. Scripted camSchnappr calibration (unit test with ground truth; real use after)
1. P1 up; `cameraCOMP proj_est` (start wrong: `tz`+0.5, `fov`40, `rx`+3).
2. `td_tox_load` `.../Palette/Mapping/camSchnappr.tox` into `/project1/pm_rig`; `td_errors`.
3. Set: `Project`=proj_est (callback `ProjectPathUpdate` clones the Project camera; wait, `td_errors`), `Geosop`=`model_target` (**nullSOP, no Material SOP**), `Projectorresw/h`=`Pw`,`Ph`, `Intrinsic`=1, `Fixaspect`=1, `Fov`=35 as the initial guess.
4. In `td_exec`: pick 8 non-coplanar model points (box corners, world coords); for each compute the true image point from `proj_true` (as P2 step 2; **verify the sign/scale with one point at screen centre before trusting**). Fallback: pinhole numpy: `x = f*Xc/(-Zc)`, `y = ...`.
5. `Clear()`; append rows to `objPtTbl` [id, tx, ty, tz, 0] and `imgPtTbl` [id, x, y, 0] (pixel offsets from centre, y up).
6. Call `op('camSchnappr').Calibrate()`; read `par.Calibrationerror` (expect < 1 px for exact data).
7. Compare `proj_est` world pose to `proj_true` (position < 1 cm, angle < 0.2 deg, FOV within 0.2 deg). Log numbers into LEARNINGS (first live proof of this route).
8. Add Gaussian noise (0.5-2 px) to image points; run N=20; report spread (how many points a human really needs).
9. Swap `proj_est` into `proj_render`; the viewer should now match P1's perfect alignment.
10. Real use: same flow with the real projector resolution; user does steps 4-5 by picking points in the camSchnappr output window; MCP does steps 6-9 and `Decompose()` for a report. Delete camSchnappr afterwards (tables live in the camera COMP).
11. `td_save_project`; if TD crashes (cv2 in Rosetta), restart (T-24, T-39).

### P5. Two-projector blend + black level + one canvas output
1. P1 up with the wall `screen` widened to 6 x 1.7; two projector cameras `projA`, `projB` looking at left/right halves, overlap ~15 %.
2. `content_out` at canvas size (2*Pw minus overlap) -> `projectorBlend` (`Projectorarray`=2 1, `Projectorres`=`Pw`,`Ph`, `Projector1overlap`/`Projector2overlap` in px, `Power`=2, `Gamma`=2.2 (or 1.8), `Luminance`=0.5, `Solidedge`=1 first to see the zone).
3. `cropTOP` for each projector region -> `projA_out`, `projB_out`.
4. Two `lightCOMP`s (P1 step 7) with `projmap`=A/B; viewer on the wall.
5. With a white frame, `analyzeTOP` on three strips (left only, overlap, right only): overlap luminance must match the neighbours (target within 2 %).
6. With a black frame, add per-projector black offsets in the rig (`constantTOP` 0.02) to simulate light leak => overlap visibly greyer.
7. Black-level uplift [U]: `rampTOP` masks (horizontal, `position` at overlap bounds) -> `compositeTOP` add `constantTOP lift` * (1-overlapMask) onto each projector output; tune until the black strip is uniform.
8. Output: `containerCOMP canvas` with A and B side by side -> `windowCOMP out` (`winop`=canvas, `justifyoffsetto`=specifydisplay, `display`=n, `size`=custom `winw`=2*Pw, `borders`=0, `cursorvisible`=nocursor, `vsyncmode`=enabled). **Do not open**; user approves `winopen`/`setperform`.
9. Mission Control checks (human): Mirror OFF, Spaces separate OFF. Layout; save.

### P6. Sweet-spot / Quad Reproject for LED or screens (general; PF26 stage proxy at the end)
1. New scene `pm_rig/led`: `geometryCOMP scr_L`, `scr_C`, `scr_R` each one `gridSOP` (`orient`=xy, `rows`2 `cols`2 `sizex/sizey`) rotated (e.g. L/R 25 degrees inward), in a parent COMP that positions them (world position is used) [V].
2. Print each grid's point positions (td_exec) and pick BL, BR, TL, TR by coordinates, since point numbering is [U].
3. 3D content: `geometryCOMP orb` (sphere/box floating in front of the screens) + `phongMAT`, `lightCOMP`, ground contact shadow (`shadowtype`=soft2d).
4. `cameraCOMP sweet` at the audience position (`lookat`=centre of screens).
5. Load `quadReproject.tox`; `Camera`=sweet, `Geometry`=orb (+ scene), `Lights`, `Number of screens`=3 (`Screens` sequence), per screen: `Sop`, `Points`=BL BR TL TR, `Resolution` (e.g. 1152x2880 for a 20 ft face, 576x2880 for 10 ft; R02 sizes in C_pf26_fit 2).
6. Outputs -> three `nullTOP`s -> `constantMAT` colormaps on three **display** quads in a second scene `viewer_scene` (emissive, unlit).
7. `view_cam` at the sweet-spot position: sees the orb continuous across the three screens; move to off-axis: orb distorts (expected). Record both screenshots.
8. Check artefacts at the returns (steep angle) [V warning]; raise grid `rows/cols`; if bad, flatten the return or hide the effect on that face.
9. Atlas assembly (PF26 only): `layoutTOP`/`compositeTOP` + `transformTOP` copy the face rectangles of `production/mapping.py` (C_pf26_fit 2) into 7488x2880; verify the sum 1152+576+576+576+1728+576+576+576+1152 = 7488. Time a 9984x3840 cook first (never timed, C_pf26_fit).
10. Optional native route: set the sweet camera's own `quadreprojsop/quadreprojpts1-4` for a single panel (no palette).

### P7. Content effects on a mapped model (light sweep, wireframe reveal, collapse)
1. P1 up (or P3). Resolution = projector `Pw`x`Ph`.
2. Add `phongMAT pos_mat` with `color0output`=worldspaceposition on the model; `renderTOP proj_render` `numcolorbufs`=2 (second colour buffer) or a second Render TOP with `overridemat`=pos_mat; read it with `renderselectTOP` (`bufferindex`).
3. `lfoCHOP`/`timerCHOP` t -> `glslTOP sweep` (Compute mode, T-47): `m = smoothstep(w,0.,abs(dot(P-P0,dir)-t))`, outputs mask.
4. Base render (dark Phong), `compositeTOP` add (base + m * colour) -> light sweep.
5. Wireframe: second `renderTOP` with `phongMAT wireframe`=topology (or `wireframeMAT`); multiply by the mask `m` (reveal) or by `1-m` (decay); `bloomTOP`.
6. Edges: `depthTOP` -> `edgeTOP` -> add (outline glow).
7. Collapse variant [U]: split the model into slab COMPs; `bulletsolverCOMP` (`gravityy`-9.8, `rate`60, `actors`=slabs, `initialize` then `start`) with the floor as a static actor; render slabs from the projector camera; blend a hole layer revealing a second scene behind the facade.
8. Cost check: `td_perf` after 5 s (T-05, T-42); target <= 8 ms render at the chosen resolution.
9. Viewer check for the audience-viewpoint rule (row 19): render the collapse from `view_cam`, project through P3.
10. Expose `t`, `w`, `dir`, colour as custom pars; layout; save.

### P8. Stoner / Kantan hand-off and bake
1. P2 up (a flat `screen`, projector at an angle, plus a slightly curved/warped second surface via `latticeSOP`).
2. `td_tox_load` `stoner.tox`; wire `content_out` -> `in1`; `Project`=`baseCOMP warp_store`; open the Stoner window only after telling the user (`Open` pulse).
3. **Human:** warp (keystone k, then grid g) until the viewer rig looks right (they can use `view_out`).
4. Close (`Close`). `td_get_pars` check `project/settings` (rows, cols, mode).
5. `remapTOP bake_check`: input1=`content_out`, input2=Stoner `out2` (`extend`=zero, `interp`=linear). Compare with Stoner `out1` using `differenceTOP`; max `analyzeTOP` < 1/255.
6. Bake: `out2` -> `nullTOP`; `TOP.save('maps/warp_A.exr')` (float; T-04 proved png save; EXR/TIF float = [U]) -> `moviefileinTOP` (`file`) -> `remapTOP` replaces Stoner. Delete Stoner (perf per docs [V]).
7. Kantan: `td_tox_load` `kantanMapper.tox`; `Project`=json path; `Open`; **human** draws 2 quads + 1 freeform mask; user presses Save Project in its UI (the MCP never calls `Collect()`/`Load()`).
8. Read the JSON (file) to document shapes (`Warp`,`Rows`,`Cols`,`Softedge`,`Texture`); re-create the layout later by reproducing `Load()` without the dialog (loop in section 1: `tree`.appendRow, `Layerizer.cookOwner`, `SetDefinition`) [U], first test on a copy.
9. Save the project; log hand-off steps in STATUS.
